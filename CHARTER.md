# Charter

## Mission

Build the judgment and systems required to delegate meaningful software-engineering outcomes to AI agents safely, repeatably, and with evidence of correctness.

The program should produce an engineer who can design, operate, evaluate, and improve agentic workflows—not merely use a coding assistant faster.

## Capability target

By the end of the program, the learner should be able to:

1. Explain the boundary between a model, an agent loop, a harness, tools, context, state, and an execution environment.
2. Design context and knowledge systems that remain useful across tasks and sessions.
3. Build tools and agent workflows with explicit authority, isolation, observability, recovery, and escalation.
4. Delegate complete product or engineering outcomes while retaining decision rights and accountability.
5. Coordinate multiple agents only when parallelism exceeds its coordination cost.
6. Define evaluations and quality gates that measure outcomes rather than fluent output.
7. Turn failures and corrections into durable improvements to instructions, tools, tests, and architecture.
8. Make informed build-versus-buy decisions about agent platforms, courses, and infrastructure.

## Principles

- **Production over demos.** Exercises must include realistic constraints, failure modes, and verification.
- **Evidence over authority.** Claims need primary sources, experiments, or explicit uncertainty.
- **Outcomes over prompts.** Optimize the complete workflow and delivered result, not prompt aesthetics.
- **Bounded autonomy.** Authority, permissions, stop conditions, and human escalation are part of the design.
- **Independent criticism.** The second agent must search for disconfirming evidence and better alternatives.
- **Durable learning.** A useful lesson changes a workflow, artifact, test, tool, or decision—not only understanding.
- **Current by construction.** Fast-moving claims expire and must be rechecked.
- **Minimal machinery.** Add orchestration only after a manual workflow exposes a concrete need.

## Program outputs

The program should leave behind a reusable engineering system containing, where justified:

- project and task context patterns;
- agent instructions and skills;
- tool and MCP designs;
- specification and planning formats;
- delegation, review, and verification workflows;
- eval suites and quality gates;
- observability, recovery, and escalation patterns;
- a decision record explaining what worked, what failed, and why.

## Non-goals

- A beginner introduction to programming, Git, APIs, testing, or software architecture.
- A catalog of AI products or a collection of bookmarks.
- Tool-specific certification training.
- Unsupervised execution against production systems.
- Multi-agent complexity for its own sake.
- Replicating MEGA lesson-for-lesson without testing relevance and currency.

## Success definition

The program succeeds when the learner can apply its workflows to a real, nontrivial software project and demonstrate:

- a larger useful delegation boundary;
- fewer unplanned human interventions;
- explicit and appropriate approval boundaries;
- reproducible verification of the delivered outcome;
- measured cost, latency, and quality tradeoffs;
- at least one failure converted into a durable system improvement.

The learner owns goals, risk tolerance, final judgment, and approval. Codex and Claude propose, challenge, implement curriculum artifacts, and surface uncertainty.
